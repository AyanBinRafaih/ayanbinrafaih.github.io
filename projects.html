AgentFlock

2026

  • TypeScript
  • PostgreSQL
  • Apache Kafka
  • Docker
  • Kubernetes

Event-sourced multi-agent orchestration platform for dependency-aware autonomous research workflows.

Multi-agent systems need to coordinate heterogeneous agents while preserving task dependencies and state across distributed execution. AgentFlock implements this as a distributed agent platform in which an API gateway accepts complex tasks, an LLM-based orchestrator decomposes them into subtasks, and specialized research, writing, review, and planning agents execute them as dependencies become available. The services communicate asynchronously through Apache Kafka, with PostgreSQL storing tasks, subtasks, events, and agent results, while Redis provides shared caching and rate limiting. A DAG scheduler tracks completed dependencies and dispatches newly unblocked work, allowing independent subtasks to execute concurrently while dependent stages wait for their required results. The system is packaged as six containerized services with Kubernetes deployment support and includes a React dashboard, Kafka monitoring, Prometheus metrics, and Grafana dashboards for inspecting workflow state and execution history.

Limit Order Book Matching Engine

2026
  • C++20
  • CMake
  • GoogleTest
  • Google Benchmark
  • GitHub Actions

Low-latency exchange matching engine using cache-efficient techniques and statistical analysis of latency distributions.

Low-latency trading systems require an order book that can maintain market semantics while keeping the matching path predictable and minimizing synchronization overhead. This project implements a C++20 limit order book and matching engine with price-time priority, multi-level matching, full and partial fills, remainder handling, and iterator-based order lookup for fast cancellation. Price levels are maintained with ordered maps, orders at each level use FIFO lists, and an order-ID index maps directly to stored iterators. The matching engine includes a lock-free single-producer single-consumer queue and a single-threaded execution path, with cache-line-aligned order storage and a CMake build configured for native optimization. Latency is measured using RDTSC with LFENCE serialization and calibration against CLOCK_MONOTONIC_RAW, while we use Google Benchmark unit tests, and statistical distribution analysis (Python) to characterise the effects of the implementation choices and trade-offs made.

Agentic loops for bespoke domain-specific serving systems, with a terminal user interface and a correctness and benchmark harness.

General-purpose systems are designed to serve a broad range of workloads, but the best implementation can depend heavily on the application requirements, workload, model, and hardware. VibeSys explores whether AI agents can instead generate and optimize bespoke systems for a specific target, using an iterative search process in which agents propose implementation changes, test them against target-specific correctness requirements, profile performance, and retain validated results in Git-backed experiment history. VibeServe is the first substantial systems project built around this approach, applying the framework to LLM serving across different workloads and hardware targets. Work on the project includes the interactive terminal interface used to inspect long agentic runs, with hypothesis logs, per-round agent traces, experiment chat, graph views of hypotheses and actions, and performance dashboards. The evaluation infrastructure was also extended with correctness and performance harnesses for DeathStarBench social-network microservice, including distributed consistency checks, open-loop load generation and end-to-end latency decomposition using Jaeger tracing (parent servers and intermediate hop-servers).

MeriZubaan

2025

  • Python
  • Firebase

Full-stack Android language learning platform with adaptive vocabulary acquisition.

Language-learning software often relies on generic vocabulary and review workflows that do not capture the linguistic structure or pronunciation needs of a specific language. This Android platform implements an Urdu language acquisition system with authentication, cloud-synchronized learner progress, weekly quizzes and adaptive spaced-repetition workflows for managing practice over time. A corpus of more than 10,000 Urdu language samples was designed and curated with phonetic annotations and native-speaker pronunciation recordings as the main dataset. The system was evaluated through structured user studies, to iteratively refine the platform through the feedback.
